## 0. 背景：平台差异（所有影响的根因）

- 原实验（2025-12，论文 Table III/IV 数字来源）与本次修订实验在不同主机：
  本机为 KVM 虚拟机，Xeon Gold 6133 @2.50GHz 固定无 turbo + 2×RTX 3090。
- 已实证（三版本代码同机 A/B + 分量归因，见归因 README）：
  - **非代码改动导致**（实验期/pre-DEV/DEV 三版本本机结果互差 <10%）；
  - 软件栈逐版本一致（torch 2.5.1+cu121 / transformers 4.57.1 / openai-whisper 20250625 等）；
  - GPU 性能两机一致（LLM 预填 +9%）；差异集中在 ASR 阶段（whisper 解码 CPU 编排敏感，+45~50%）。
- **需求方裁决（2026-08-19，已生效）**：
  - A. 环境披露须覆盖 Table IV（不止新增表格）；
  - B. **红线：不对本机数字做任何缩放去对齐旧机绝对值**；
  - C. 本机 QA sanity 带更新（System B long+ 1.2–1.7s；System A extra_long 7.5–10.5s）；
  - D. 摘要/结论中的绝对数字须绑定平台表述；
  - exp1/exp2 全量不重做（硬证据：repeat 子集改进率 65.6%→64.7% 稳定）。

## 影响项 1（E3-AB，2026-08-20）：改善率 74.3% → 70.4%（同 498 样本两机对齐）

- 数据（同 498 消融清单成对比较）：

  | 指标 | 旧机 exp2 | 本机重跑 | 变化 |
  |---|---|---|---|
  | System A mean TTFT | 4503.1ms | 5310.8ms | +17.9% |
  | System B mean TTFT | 1155.5ms | 1573.9ms | +36.2% |
  | 汇总改善率 | 74.3% | 70.4% | −3.9pt |
  | 逐样本改善率 mean | 65.0% | 59.9% | −5.1pt |

- 机制：System B 的 ASR 流式编排更 CPU 敏感，慢 CPU 上被抬高更多 → A−B 差距收窄约 4pt。
- **对论文的影响**：
  1. 核心结论（流式大幅降 TTFT、长语音收益最大）方向/量级/显著性不变，**无需改结论**；
  2. 修订新增 LA 对比表必须用本机同机三方数字（A 5310.8 / B 1573.9 / LA 待 E3-LA），不得与 Table IV 旧绝对值混排；
  3. 若摘要/结论有"约 74%"类绝对表述，建议改为"70%–74%（两平台复现）"或绑定平台（裁决 D）。
- **待决事项（实验全部跑完后决策）**：exp2 中间消融臂 `streaming_asr_only`（旧机 1171.0ms）未重跑；若 LA 对比表引用该臂，选择：(a) 脚注标明为原平台数字；(b) 本机补跑 `run_exp_ablation` 498 清单（约 +4 GPU 小时）。

## 影响项 2（E2b，2026-08-19）：babble 噪声下流式显著退化（对作者不利方向的新发现）

- 数据：librispeech_babble streaming 3425ms vs non-streaming 2326ms（**−47.3%，流式反而更慢**）；aishell1_babble +6.5%（几乎无收益）。其余 10 个 snr/speed 变体改善率 +22.8%~+31.6% 正常。
- 机制（已归因，非缺陷）：VAD 对多人 babble 过度触发 → 段积压（最慢样本音频结束后 21s 才排空 ASR 队列）；whisper 对噪声段大量空输出（librispeech 12/30、aishell1 5/30 空转写）；长尾分布（median 2020ms）。
- **对论文的影响**：
  1. 若论文有"流式在各种噪声条件下均优于非流式"类强表述，需要加 babble 例外或在 limitations 中讨论；
  2. 审稿回复中可作为鲁棒性边界条件主动披露（诚实数据，审稿人视角是加分项）；
  3. 下游分析注意：空输出样本的 `asr_time`/`llm_prefill_time` 为哨兵值（`last_text_time=0`），统计时应剔除零提交样本；`ttft` 不受影响。
- **待决事项**：babble 结果是否进正文表格（10 变体 vs 12 变体口径）待论文侧决策。

## 影响项 3（E1，2026-08-19）：绝对延迟水平上移，稳定性结论不受影响

- 数据：三轮 streaming TTFT mean 1434/1482/1455ms（repeat 子集全 very_long），同 50 样本旧机 981ms（+46%）；跨轮 mean 极差 3.3%，逐样本 CV median 3.3%。
- **对论文的影响**：
  1. 意见3 的回应（测量可复现性）证据充分，与绝对水平无关；
  2. 修订稿任何引用 E1 绝对数字处须绑定平台（裁决 D）；response letter 建议附一句"重复性在第二平台复现，CV<5%"。
- 无待决事项。

## 影响项 4（E3-LA，2026-08-20）：DEV-3 实现 bug 导致本轮 LA 结果无效 → 已修复（commit `6d74c1c`），待 GPU 机重跑

- 现象：LA WER mean=0.545（异常高），79% 样本转写长度不足 System B 的 70%，提交文本中间被整段跳过。
- 机制（逐轮重放实证）：`_trim_buffer()` 裁剪音频缓冲后，`n_committed`/`prev_words` 仍引用裁剪前的"全序列帧"下标，而下一轮重解码的假设是"尾段帧"——下标错帧导致提交跳过新假设前 n_committed 个词，中间文本静默丢失，flush 丢尾。
- 处置：结果已标记 `*.INVALID_dev3_frame_bug` 保留现场；评审（`experiments/review/20260820-E3LA/`）判定定位与无效处置成立。
- **修复（2026-08-20 完成）**：绝对时间轴提交 + 标点鲁棒一致比较 + 句界裁剪（修复过程中另发现"句末残片开头缓冲触发 Whisper turbo 幻听坍缩"的第二个机制，一并修复）；回归 16/16；典型样本回放 WER 0.8796→0.0185。详见 REVISION_CHANGELOG 2026-08-20 修复条目。
- **对论文的影响（暂定）**：意见4 的 LA 对比数据待重跑后入表；不影响 E1/E2/E4/E5 的有效性（LA 组件独立于 System B 路径）。**论文方法描述注意**：若正文/回复中描述 LA-2 基线实现，应写修复后语义（绝对时间轴提交 + 句界裁剪），避免与 ufal 原版描述产生出入时被追问。
- **待决事项**：GPU 机 E0 冒烟 + 全量重跑排期（前置条件见 GPU_EXPERIMENT_HANDOFF §E3）。

## 影响项 5（E4，2026-08-20）：turbo 下已提交文本重识别漂移实测存在（224 条/50 样本）

- 数据：50 样本 commit_log.jsonl 共 375 条 commit + **224 条 correction**（已提交段在后续轮次重识别中文本变化，下游不会再收到新文本）。
- 解读：append-only 声明在"对下游输出"层面成立（无回滚下发），但"已提交文本在内部重识别中从不变化"不成立——turbo 下也频繁漂移（多为同音字/标点级，见 commit_log.jsonl）。
- **对论文的影响**：意见5 的回应中，"无回滚"表述应精确为"对已提交输出无回滚；内部重识别存在漂移观测（N=224/50 样本），下游不可见"。若论文原文有更强的"内部一致性"声明，需按实测数据软化。
- 备注：full_response 50/50 完整（mean 208 字符，max_tokens=128），可供分词接缝与语义一致性离线分析；结果 JSON config 块未含 save_* 开关位（checkpoint config 有），记录完整性小瑕疵。

## 影响项 6（E5，2026-08-20）：端点等待量级——检测等待很小，瓶颈在后端处理

- 数据（50/50 有效样本，尾拼 2s 静音）：
  - `endpoint_detection_wait`（语音结束→最后语音段入队）mean **53ms** / median 109ms / p90 208ms；
  - `final_enqueue_wait`（语音结束→is_final 段入队）mean 2053ms ≈ 追加静音长度（设计内：flush 段要等静音推完）；
  - `post_endpoint_ttft`（端点入队→首 token）mean **3012ms**（ASR 末段转写 + LLM 预填解码，本机 CPU 偏移含在内）；
  - total（speech_end→首 token）mean 3065ms。
- **对论文的影响**：意见2 的 TTFA 预算表中，"端点检测等待"一项在本管线（VAD 闭段驱动 + suffix=0）下贡献很小（~0.05–0.11s），主要预算在末段 ASR+LLM（~3.0s，本机口径）。撰写时注意两点：① 该绝对值含本机 CPU 偏移，原机口径预计 ~2.1s 左右（按 ASR +46% 推算，仅作参考不可混排——红线 B）；② final_enqueue_wait 的 2s 是追加静音的测量装置属性，不是系统等待。

## 影响项 7（E6，2026-08-20）：TTS 首包是 TTFA 预算的最大项，且 TTFC 与回复长度近似线性

- 数据（50 条 E4 full_response，中英各 25，error 0）：
  - TTFC mean：zh 13.99s / en 11.86s（回复均长 ~200 字符）；total mean ~33–35s；RTF ~0.71。
  - 预热对照：冷 14.84s vs 热 12.92s（9 条 vs 50 条），**排除预热因素**（需求方建议的检验，已执行）。
  - 长度诊断（单次）：3 字符→TTFC 1.37s，17→3.77s，45→7.64s，200→17.93s；短句首包≈整段合成完才到 → 该部署为**句段级流式**。
- **对论文的影响**：
  1. 意见2 的 TTFA 预算表结构改变：TTS 首包（~12–14s @200字符回复）≫ 管线侧 total（E5：语音结束→首 token 3.1s）≫ 端点等待（0.05s）。若论文曾声称"TTS 流式首包很快"，需要按实测修正；
  2. 建议论文给出 TTFC 与回复长度的关系（近似线性 ~0.09s/字符），或限定结论于"短回复"场景；
  3. 平台口径：TTS 前端 CPU 敏感，本机 KVM 2.5GHz 放大了 TTFC/RTF（裁决 D 绑定平台）；如需原机口径需在原机补测（数据生成那台）；
  4. 服务侧 spk 别名补丁（晓伊→中文女）仅影响音色、不影响延迟（见 TTS_SERVICE_HANDOFF §三），无需披露为实验误差，但若论文描述音色需留意。
- **待决事项**：是否需要在原机（或更高主频 CPU 机器）补测 E6 作为对照。
