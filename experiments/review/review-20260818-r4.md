## 二、仍需处理的问题

### R4-P1-1：回归测试没有验证 `run_exp_latency.py` 的生产时间字段

**严重程度**：中
**涉及文件**：

- `experiments/scripts/test_revision_regressions.py:110-120`
- `experiments/scripts/test_revision_regressions.py:130-165`
- `experiments/scripts/run_exp_latency.py:645-659, 763-779`

当前回归套件的 endpoint B1-B4 只调用 `StreamAudioSegmenter`，检查：

- 中途段是否 `contains_speech`；
- flush 段是否 `contains_speech`。

但真正写入论文实验结果的字段和错误分类是在 `run_exp_latency.py` 中完成的：

- `speech_end_time`；
- `final_speech_segment_commit_time`；
- `final_is_final_segment_enqueue_time`；
- `asr_no_speech`；
- endpoint wait 的计算基础。

目前没有自动测试以下不变量：

```text
speech_end_time > 0
final_is_final_segment_enqueue_time > 0
含语音样本的 final_speech_segment_commit_time > 0
全静音样本的 final_speech_segment_commit_time == 0
final_speech_segment_commit_time <= final_is_final_segment_enqueue_time
```

因此，当前 8/8 PASS 证明了 `contains_speech` 的分段层逻辑，但没有完全证明生产脚本最终写入 JSON 的时间字段和 error 字段正确。

**修改建议**：

增加一个不依赖模型的 endpoint bookkeeping 测试，推荐将 `run_exp_latency.py` 中的时间字段判定抽成纯函数，例如：

```python
def classify_endpoint_times(
    speech_end_time,
    final_speech_segment_commit_time,
    final_is_final_segment_enqueue_time,
    existing_error="",
):
    ...
```

然后测试：

1. 正常语音 + 尾静音：两个 final 时间非零，`asr_no_speech` 不产生；
2. flush-only 语音：语音提交时间和 final enqueue 时间均非零；
3. 全静音：语音提交时间为 0，final enqueue 时间可非零，结果标记 `asr_no_speech`；
4. 时间顺序不合法时显式报错或标记异常。

如果不抽函数，也可以在测试脚本中建立 stub 线程/segmenter，直接运行生产 bookkeeping 逻辑。但不能只测 `StreamAudioSegmenter` 后就声称 E5 的生产字段已被验证。

**验收标准**：

回归输出中应明确打印或断言三个时间字段及其关系，而不仅是 `contains_speech`。

### R4-P2-1：B2 测试没有断言 fixture 真的是 flush-only

**严重程度**：低到中
**涉及文件**：`experiments/scripts/test_revision_regressions.py:140-146`

B2 测试当前只断言：

```python
rem is not None and rem.contains_speech
```

但没有断言：

```python
mids == []
```

因此，如果 fixture 实际在中途已经闭合过一个或多个语音段，同时 flush 又剩余一段含语音内容，测试仍然会通过，但它不再是严格的 flush-only 回归场景。

**修改建议**：增加：

```python
assert mids == [], f"fixture 不是 flush-only，检测到 {len(mids)} 个中途段"
assert rem is not None and rem.contains_speech
```

如果 fixture 由于 VAD 的平台差异确实可能产生中途段，则不要称为 flush-only，应改名为“flush residual speech”并按实际场景重新定义验收条件。
