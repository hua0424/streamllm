# E3-LA 问题报告评审（2026-08-20）

## 结论

报告对 E3-LA 结果无效原因的定位基本成立，当前 `LocalAgreementStreamer` 的状态机确实存在“音频缓冲裁剪后，仍使用裁剪前假设序列的 `n_committed` 下标”问题。该问题会把裁剪后新假设中的未提交词误认为已经提交，导致文本中段静默丢失，并进一步污染 WER/CER、提交日志、LLM 输入和基于该策略的 TTFT。因此，现有 E3-LA 全量结果不应用于论文比较，标记为 `INVALID_dev3_frame_bug` 并保留备查是正确处理。

建议：**暂停使用现有 E3-LA 结果，先修复实现并通过回归和冒烟验收，再删除/移走旧 checkpoint 后全量重跑。**

## P0：根因定位正确，现实现会跨帧错用提交下标

**位置：** `src/asr/local_agreement_streamer.py:141-157, 160-168, 192-206`

当前流程在提交后执行 `_trim_buffer()`：

1. `n_committed` 表示裁剪前 `prev_words` 中已经提交的词数；
2. `_trim_buffer()` 只裁剪 `buffer`、平移 `prev_words` 时间戳和 `last_committed_end`；
3. 下一轮 `_decode_buffer()` 产生的 `cur_words` 已经是裁剪后尾部缓冲区的局部词序列，词 0 不再对应裁剪前完整假设的词 0；
4. 代码仍执行 `agreed[self.n_committed:]`，并在 `flush()` 中执行 `prev_words[self.n_committed:]`。

因此 `n_committed` 的序列帧与当前 `prev_words`/`cur_words` 的序列帧不一致。报告中的典型重放与代码行为一致：前面已提交 12 词后，裁剪使下一轮假设从尾部重新编号，但 `n_committed` 仍为 12，后续提交会跳过新帧中前 12 个尚未提交的词。该错误不是统计脚本问题，也不是单纯的模型质量波动，而是提交状态的语义错误。

影响范围包括：

- `transcribed_text` 不再代表 LA-2 实际应提交的完整序列；
- WER/CER 系统性失真，报告中的高 WER 和转写长度比异常具有明确的代码层解释；
- LLM 收到的增量文本被截断，LA 的 TTFT 不再是可与 System B 公平比较的策略结果；
- `divergence_count` 也会受到错帧状态影响，不能作为当前结果的可靠诊断统计。

## P0：现有结果必须作废，不应只修统计或按样本剔除

报告建议将现有结果标记为无效并保留现场，判断正确。该缺陷发生在逐样本在线提交路径，影响不是少数异常样本，不能通过删除高 WER 样本、重新计算均值或扩大误差范围修复。

System A/B、E1/E2/E4/E5 是否受影响，需要以实际调用路径为准。就当前报告提供的信息和代码结构看，`run_exp_baseline_la.py` 专用 LA 路径使用 `LocalAgreementStreamer`，而 `run_exp_latency.py` 的 System A/B 不直接依赖该类，因此“E3 失效、其他实验不因该类直接失效”的判断合理。但若其他实验在同一提交期间读取或导入该类，应以运行配置和结果日志再次确认，不能仅凭目录名称推断。

## P1：修复方向合理，但建议避免只做“清零下标”的局部补丁

报告提出的三个方向是合理的：

- 裁剪后重置当前假设帧的 `prev_words`/`n_committed`；
- 使用时间下限而不是跨帧词数下标判断新提交词；
- `flush()` 同样按时间语义处理剩余词。

但实现时需要明确区分两类状态：

1. **跨样本/跨帧持久的已提交文本边界**：例如累计提交文本，或绝对音频时间轴上的 `last_committed_end`；
2. **仅属于当前裁剪后假设帧的 LocalAgreement 比较状态**：`prev_words` 与该帧内的提交位置。

仅在 `_trim_buffer()` 中设置 `prev_words=[]`、`n_committed=0`，如果没有同步定义下一轮如何建立 LocalAgreement 的比较基准，可能会把“裁剪后的第一轮假设”直接当作稳定文本提交，削弱 LA-2 的两轮确认约束。因此修复应明确写出：裁剪后第一轮是新帧基线，哪些词必须等待下一轮相同假设确认，哪些词可依据既有提交边界直接排除；并用测试证明不会重复提交、回撤或跳过文本。

更稳妥的实现要求是：提交起点以绝对/累计时间边界表示，公共前缀比较只在同一缓冲帧内进行；裁剪后重新初始化帧内假设簿记，同时保留独立的累计提交文本和音频时间边界。若采用纯时间过滤，也必须处理时间戳重叠、重复词和 Whisper 在裁剪边界附近重新对齐的情况。

## P1：必须补充的回归测试

报告列出的回归方向正确，但建议把验收细化为以下最小集合：

1. **跨帧跳段测试**：构造“提交前缀 → 裁剪 → 新假设前缀不同 → 再次提交”的模拟词序列，断言累计提交文本包含中间未提交词，不能只断言末尾词存在。
2. **无重复测试**：连续多个裁剪周期后，累计提交文本中每个稳定词只出现一次。
3. **边界重叠测试**：词的 `start/end` 落在 `last_committed_end ± 0.1s` 附近时，不能重复或跳过。
4. **flush 测试**：在发生至少一次裁剪后直接 flush，尾部剩余词全部提交，且不重复已提交文本。
5. **空识别恢复测试**：保留已有 A1 语义，空识别后下一次有效识别仍能提交完整剩余文本。
6. **真实样本回放**：使用报告中的 `crosswoz_10296_turn2`，保存修复前后提交片段、最终文本和 WER，确认中段不再丢失。
7. **生产路径测试**：通过 `run_exp_baseline_la.py` 的真实 `run_single_sample()` 路径验证队列收尾、LLM 收尾和结果字段，而不只直接单测 streamer。

测试应在 `test_revision_regressions.py` 中可重复运行，并在报告或 changelog 中记录通过数量和关键断言。不能只凭一次 2 样本冒烟宣称修复完成。

## P1：重跑前还需要核对的实验语义

修复后 E0 冒烟和全量 E3 重跑前，应额外核对以下项目：

- E3 命令显式锁定 `--suffix-segments 0`，并在结果 `config` 中核对 `trailing_margin_s=0.0`；
- ASR 与 LLM 设备分别为 `cuda:0` 和 `cuda:1`，不能使用默认 `auto`；
- 使用同一份 498 条 clean paired sample list，清单缺失样本应停止而不是静默缩减；
- 删除或移走旧 `checkpoint.json` 以及带 `INVALID_dev3_frame_bug` 的结果，避免续传混入无效样本；
- 保留完整命令、代码版本、模型名、设备、样本数、错误数和起止时间；
- 全量结果的 error 数应为 0，或对任何异常样本给出逐样本解释；
- 重新检查 LA 转写长度比、WER/CER、divergence_count 和 TTFT 分组统计，重点观察是否回到与同引擎 System B 可解释的量级；
- 不能把“WER 接近 System B”作为唯一验收标准。还必须检查提交片段拼接、无重复/无跳段、LLM 收到的文本以及 `flush()` 尾部行为。

## 对报告中具体结论的评定

- “E3-LA 498/498、error 0 但结果无效”：**同意**。运行无异常不代表算法状态正确。
