## 已确认修复项

### 1. 原错帧缺陷已移除

`src/asr/local_agreement_streamer.py` 不再使用跨裁剪帧的 `n_committed` 词数下标。当前实现将：

- `buffer_start_abs`；
- `committed_words`；
- `committed_end_abs`；
- `prev_words` 中的未提交区域

统一放在绝对音频时间轴上，并使用时间边界判定新提交词。这样，缓冲裁剪后新一轮假设从局部词 0 重新开始时，不会再把旧帧的提交词数误用于新帧。

`D1` 测试确实覆盖了上一轮报告要求的关键序列：提交 → 句界裁剪 → 新假设前缀变化 → 再提交，并断言中段 `m1/m2` 正常提交、最终序列无缺无重，且不是靠 flush 兜底。

### 2. append-only 和重复防护有独立状态

修复不是简单清零 `prev_words`/`n_committed`，而是保留累计的 `committed_words` 和绝对提交边界，同时让 `prev_words` 只保存当前未提交区域。这满足了上一轮提出的“跨帧持久提交边界与帧内比较状态分离”的要求。

`_in_uncommitted_region()` 和 `_is_duplicate_of_committed()` 对裁剪保留区内的重识别词做时间区间及规范化文本去重；`D2`、`D3` 对多次裁剪和边界重叠进行了覆盖。

### 3. flush 和空识别状态得到覆盖

`flush()` 改为按绝对时间边界筛选剩余词，并清空 `prev_words`，二次调用幂等。`D4` 覆盖了裁剪后 flush、无提交时 flush 以及二次 flush。

空识别分支保留上一轮未提交假设，`A1` 验证后续有效识别仍能恢复并提交完整文本。

### 4. 真实回放证据支持修复有效

`replay_crosswoz_10296_turn2_fixed.json` 记录：

- 修复后 WER：`0.0185185`；
- CER：`0.0727273`；
- 5 个提交片段；
- 100 个已提交词；
- 典型中段文本不再丢失。

该结果与修复前 WER `0.8796`、短文本及中段跳失现象形成直接对照，足以证明原错帧机制在代表性样本上已消失。

### 5. 生产路径和运行前置已补齐

`D5` 使用真实 `LAExperiment.run_single_sample()`、真实 segmenter、线程队列和 fake LLM，验证了：

- 生产收尾能够产生首 token；
- 提交文本连续无缺无重；
- LLM 收到的文本等于 ASR 提交文本；
- 无 error。

`run_exp_baseline_la.py` 对 sample list 缺失改为硬失败，避免 498 条成对子集被静默缩减；`la_max_buffer_s` 写入结果配置。handoff 也已加入 E0、旧 checkpoint 隔离、配置核对和全量 QA 要求。

## 保留的非阻塞注意事项

### 1. 本地回归不是正式模型验收

16/16 回归中的 D1-D6 主要使用脚本化词序列、fake decode 或 fake LLM；真实模型证据目前是单个 `crosswoz_10296_turn2` turbo 回放。因此这些证据足以批准进入 E0，但不能替代：

- GPU 主机上 turbo + Qwen2-7B 的 E0；
- 498 条样本全量 E3；
- 全量结果的 WER/CER、长度比、TTFT 和 error QA。

### 2. 句界裁剪是方法学行为变化，需在结果中锁定并披露

修复同时加入了“优先在句末已提交词裁剪、无句界且超过 15 秒时按提交边界强制裁剪”的策略。这解决了回放中由句末残片引发的 Whisper 幻听，但它不再是原先简单的 `last_committed_end - 0.1s` 裁剪实现。

这不是本轮阻塞，因为 handoff 和 changelog 已记录该行为，并将 `la_max_buffer_s=15.0` 写入 config。全量 E3 结果和论文方法部分必须使用同一配置，不能重跑后只报告“LocalAgreement-2”而省略该缓冲裁剪规则。

### 3. 回放与正式 E3 的时间语义不同

`replay_la_sample.py` 明确跳过实时 sleep，用于算法回放，这是合理的；正式 `run_exp_baseline_la.py` 仍保留实时 chunk sleep。回放结果只能用于正确性证据，不能用于 TTFT 或吞吐量数字。

### 4. 正式 QA 仍需检查提交片段，而不只看总体 WER

全量重跑后应至少抽查：

- `transcribed_text` 是否存在明显中段跳失；
- 提交片段拼接是否重复；
- flush 是否重复尾部；
- `divergence_count` 是否出现异常爆炸；
- LA/System B 转写长度比是否回到可解释量级；
- config 是否包含 `trailing_margin_s=0.0`、`la_max_buffer_s=15.0`、`asr_device=cuda:0`、`llm_device=cuda:1`。

如果全量 E3 的统计再次出现高 WER、长度比显著低于 1 或大量异常 divergence，应停止并保留现场，不能以“模型随机性”解释后继续入表。
