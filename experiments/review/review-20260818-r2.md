## 二、仍需修复的问题

### R2-P0-1：LocalAgreement 空识别后可能静默丢失文本

**严重程度**：高
**状态**：未完全修复，必须修改

**涉及文件**：

- `src/asr/local_agreement_streamer.py`
- 重点位置：`feed_segment()` 中处理 `not cur_words` 的分支，以及 `flush()`。

当前逻辑在 `_decode_buffer()` 返回空结果时会清空上一轮假设：

```python
if not cur_words:
    self.prev_words = []
    return []
```

但没有同步重置 `self.n_committed`。

如果此前已经提交了 2 个词，随后某轮临时识别为空，则状态可能变为：

```text
prev_words = []
n_committed = 2
```

下一轮重新识别得到较短的词序列时，`flush()` 使用：

```python
remaining = self.prev_words[self.n_committed:]
```

可能直接得到空序列，导致后续恢复出的文本未被提交。该过程可能没有抛异常，因此会形成“实验完成但转写文本缺失”的静默数据错误。

这与开发回复中“后续轮次公共前缀可以自然恢复，flush 不会永久卡死、不存在静默丢失”的结论不完全一致。该结论只有在空识别不破坏 `prev_words` 状态时才成立。

**推荐修改方案**：

优先不要在空识别时清空上一轮假设：

```python
if not cur_words:
    self.new_audio = 0.0
    return []
```

这样可以保留上一轮 `prev_words` 和 `n_committed`，等待下一轮重新识别。

如果业务上必须清空假设，则必须同时处理计数和审计事件，例如：

```python
self.prev_words = []
self.n_committed = 0
self.last_committed_end = 0.0
self.divergence_events.append({
    "type": "empty_hypothesis_reset",
    ...
})
```

但这种重置会改变状态语义，必须在论文实验方法中说明，并验证不会重复提交已提交文本。

**必须增加的回归测试**：

使用 mock model 依次返回：

```text
round 1: hello world
round 2: empty
round 3: hello world again
round 4: hello world again more
```

验收标准：

- round 2 不会造成后续文本丢失；
- `again` 和 `more` 最终可以提交；
- `hello world` 不会重复提交；
- 如果发生状态重置，有 divergence/reset 事件记录；
- 没有“无异常但文本不完整”的结果。

建议再增加一个测试：

```text
round 1: hello world
round 2: hello word
round 3: hello word again
```

验证已提交文本保持 append-only，同时失配被记录。

### R2-P0-2：无语音样本时错误设置 `final_speech_segment_commit_time`

**严重程度**：中高
**状态**：未完全修复，必须修改

**涉及文件**：

- `experiments/scripts/run_exp_latency.py`
- 重点位置：`segmentation_worker()` 的 flush 逻辑。

当前逻辑类似于：

```python
if remaining_segment.is_speaking or last_speech_commit == 0.0:
    last_speech_commit = flush_commit
```

当音频全程没有被 VAD 识别为语音时：

- `last_speech_commit == 0.0`；
- flush 产生的段可能只是静音残余；
- 代码仍然把 `flush_commit` 赋给 `final_speech_segment_commit_time`。

这会使一个静音 flush 段看起来像“最后一个含语音段”。它违反了字段定义：

> `final_speech_segment_commit_time`：最后一个含语音段入队时刻。

也会使 endpoint wait 统计包含没有真实语音的样本，污染端点等待结果。

**推荐修改方案**：

只有确认 flush 段包含语音时，才更新语音段时间：

```python
if remaining_segment.is_speaking:
    last_speech_commit = flush_commit
```

如果整个样本没有任何含语音段，则保持：

```python
final_speech_segment_commit_time = 0.0
```

并增加结果字段或错误标记：

```text
has_speech_segment = false
error = "asr_no_speech"
```

建议同时保留：

- `final_speech_segment_commit_time`：只允许表示含语音段；
- `final_is_final_segment_enqueue_time`：无论内容是否为静音，只表示 final 段入队时间。

统计 endpoint wait 时只使用 `has_speech_segment=true` 的样本。

**必须增加的回归测试**：

1. 正常语音 + 2000ms 尾部静音；
2. 全部静音；
3. 极短、未达到 VAD 最小语音长度的音频；
4. 没有追加静音、依靠 flush 结束的正常语音。

验收标准：

- 正常语音能得到两个时间字段；
- 全静音样本不会伪造 `final_speech_segment_commit_time`；
- `final_is_final_segment_enqueue_time` 可以单独记录 final 段入队；
- endpoint 统计不会把无语音样本纳入有效端点等待分布。

## 三、建议修复但不阻塞当前结论的问题

### R2-P1-1：`make_exp2_clean_source.py` 硬编码 dated 路径

**涉及文件**：`experiments/scripts/make_exp2_clean_source.py`

当前脚本把 dated 的输入和输出路径直接写在源码中，而且没有 CLI 参数。该脚本只能针对当前这一次 exp2 文件运行，无法方便复用于新结果。

**建议**：增加可选 CLI 参数：

```text
--results-json
--summary-csv
--gains-csv
--output-clean
--output-exclusions
```

保留当前路径作为默认值即可，但实际输入输出应写入生成文件 metadata 或日志。

**理由**：该脚本用于生成论文数据源，应该具备可复现和可复用性；否则后续重新运行 exp2 时需要直接编辑源码。

## 四、对开发回复中“部分接受”的评价

开发对 P0-3 的技术澄清是正确的一部分：

- `cache_prompt(..., is_end=True)` 会追加 generation prompt；
