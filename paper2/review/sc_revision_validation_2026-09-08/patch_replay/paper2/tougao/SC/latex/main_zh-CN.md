## 摘要

在级联式语音对话系统中，打断（barge-in）会使语言模型生成、文本转语音（TTS）合成与软件播放三者产生异步推进。我们将由此产生的上下文校正形式化为**外部进度条件化的联合前缀状态修复**（external-progress-conditioned joint prefix-state repair）。软件已消费采样点游标（software-consumed-sample cursor）经由 TTS 片段被解析为一个合法的助手 token 提交边界；随后，键值（KV）缓存、注意力掩码、token 台账、位置推进、内容跨度、角色阶段与轮次结束（EOT）状态被联合变换。在冻结的 Qwen2-7B-Instruct、Transformers、BF16 与 SDPA 配置下，一项仅针对精确性的（exact-only）评估覆盖了 24 个用例、27 次裁剪事件与 60 个恢复步。相对于对同一裁剪前快照的直接逐层切片，全部生产裁剪在 28 个 KV 层上逐位精确；27 个错误长度对照全部被检出；在已获采纳的那次运行内，匹配的恢复分支逐步保持精确。一项固定协议微基准测得，在 256–8192 token 上下文上，联合裁剪与角色修复耗时 31.054–48.315 ms；重新预填充与修复耗时的中位数之比从 2.254 升至 40.620。一项下游固定轨迹探针在四种自动化操作化（operationalization）方式下，得到"生成减去播放"的差值为 −3.37 至 −1.58 个百分点，且所有对话簇 95% 置信区间均跨零。上述证据支持软件边界处的直接裁剪完整性与同次运行内匹配分支恢复精确性；它并不确立干净重预填充等价性、设备或声学播放边界、人类语义层面的效应，也不确立生产环境的端到端延迟。

**亮点（Highlights）**

- 软件游标解析出一个合法的助手 token 提交边界。
- KV、掩码、token、位置、角色与 EOT 状态被联合修复。
- 全部 27 次生产裁剪与直接的逐层前缀切片完全一致。
- 已采纳运行中，匹配恢复在 60 步内保持精确。
- 固定协议下的修复避免了长上下文重预填充的开销。

**关键词**：级联式语音对话 · 打断（barge-in） · 播放游标 · 前缀状态修复 · KV 缓存 · 对话历史

## 1 引言

打断暴露了一个交互式语音系统特有的状态一致性问题。当用户在助手回复播放期间开始说话时，语言模型生成、文本转语音（TTS）合成与软件播放可能已推进到不同位置。语言模型可能已经生成了某个后缀，而合成器只将其部分转换为音频、播放器则尚未消费。提交完整的生成回复，会使下一轮依赖于超出所观测播放路径的信息；反之，丢弃整个助手轮次，则会同时损失已保留的前缀及其计算结果。因此，停止音频只是打断处理的一部分：级联系统还必须决定哪一段助手前缀保持提交状态，并使对话的所有表示形式都与该决定一致。

这一问题需要对"进度"的精确刻画。我们区分三类量：**软件已消费采样点**（software-consumed samples）、**设备已呈现采样点**（device-presented samples）与**声学上被听到的内容**（acoustically heard content）。第一类量由播放软件上报；第二类量还取决于应用程序、操作系统、驱动与设备缓冲；第三类量则进一步受换能、传播以及听者环境影响。本工作仅观测软件已消费采样点游标。因此，"播放条件化"（playback-conditioned）指由该软件游标驱动的状态操作，而非以 token 级粒度获知什么内容到达了设备、或听者听到了什么。

级联式"自动语音识别（ASR）—大语言模型（LLM）—TTS"系统仍然具有吸引力，因为其各组件可以被独立选择、插桩与优化。近期工作涉及语义触发、增量推理、打断控制与流式合成（Zou et al., 2026；Mai, 2026；Chen et al., 2025；Du et al., 2024）。预测式 ASR 还可利用部分识别结果，在输入最终确定之前预先准备下游结果（Schwarz et al., 2023）。在《Speech Communication》上，相邻研究考察了面向电话对话处理的低延迟集成（Morrone et al., 2024）、电信时延对说话人切换时机的影响（Edwards, 2025），以及面向语音 LLM ASR 的对话历史提示（Zheng et al., 2026）。然而，更快或更早的计算并不能决定哪些已生成内容应当在打断后保留下来。

播放条件化的历史截断已是成熟的工程实践。OpenAI Realtime API 接受一个 `audio_end_ms` 边界，并移除未播放的音频及其关联转录文本（OpenAI, n.d.）。Azure Voice Live 提供 `auto_truncate`，可在打断发生后更新前一条回复与会话上下文，并在其估计中记载了实时播放假设（Microsoft, 2026）。LiveKit 暴露了旨在使存储的转录历史与语音输出对齐的打断语义（LiveKit, n.d.）。因此，我们并不主张"历史应反映已播放输出"这一一般性原则；我们也不把缓存缩短当作新事物，因为 Transformers 已经提供了 `DynamicCache.crop` 操作（Hugging Face, 2025a,b）。

本研究的对象更窄且跨层：一份**外部进度条件化的联合前缀状态修复契约**。软件游标经由 TTS 片段元数据被解析为一个合法的助手提交边界；随后，该边界被一致地施加于 transformer 的键值（KV）缓存、注意力掩码、完整 token 台账、助手内容跨度、位置推进以及聊天角色/轮次结束（EOT）状态。这些组件无法被独立修复：长度正确的缓存仍可能编码一段无效对话，只要其掩码、台账、位置或角色边界指向另一个前缀；反过来，仅编辑转录文本并不能确保保留的模型状态确实表示该转录。

该契约分为四层。第一层是**边界解析**：将软件游标经 TTS 片段映射到一段助手 token 跨度。第二层是**联合状态表示**：将缓存、掩码、台账、内容跨度、位置与角色/EOT 状态视为一个耦合对象。第三层是**不变量保持转换**：定义裁剪与角色重开，且不重复或错误归类结构性 EOT。第四层是**可证伪验证**：将生产裁剪与同一裁剪前快照的直接逐层切片比较，施加错误长度负对照，并从相同保留状态出发检查匹配恢复。

本文按证据重要性递减的顺序处理五个问题。**RQ1** 询问联合修复在冻结模型/后端下是否满足直接裁剪完整性与同次运行内匹配分支恢复精确性，以及其固定协议开销是多少。**RQ2** 使用固定轨迹与自动化的信息复现探针，比较"软件游标保留"与"完整生成保留"。**RQ3** 刻画软触发如何影响候选可用率、丢弃 token 比例，以及一个乐观的同步预言机延迟下界。**RQ4** 审计"整串分词/整段预填充"与"分段分词/增量前向"两种实现路径，同时承认二者并非 token 等价。**RQ5** 描述三种被打断历史的自然化实现；其现有轨迹不允许进行因果比较。

唯一的核心机制贡献是如下已实现路径：

$$
\text{软件游标}\;\rightarrow\;\text{TTS 片段}\;\rightarrow\;\text{助手 token 跨度}\;\rightarrow\;\text{KV 裁剪}\;\rightarrow\;\text{角色/EOT 恢复}
\tag{1}
$$

在冻结的 Qwen2-7B-Instruct、Transformers、BF16 与缩放点积注意力（SDPA）配置下（Yang et al., 2024），已获采纳的仅精确性评估覆盖 24 个用例、27 次裁剪事件与 60 个恢复步。保留的生产状态在 28 个 K/V 层上与同一快照的直接逐层切片逐位精确；全部错误长度对照均被检出；匹配恢复分支在已采纳运行内逐步保持精确。这些结果**仅**支持直接裁剪完整性与同次运行内匹配分支恢复精确性。更早的干净重预填充协议仍维持被拒结论；已采纳协议不确立干净重预填充等价性或续写等价性，也不确立跨模型、跨后端或跨硬件的正确性。

其余研究提供支持性或探索性证据。一项固定轨迹的下游探针在四种自动化操作化方式下产生了不确定的差异，它不是人类语义层面或人机交互层面的评估。候选生成在一个同步分段文本试验台（harness）中评估，其时间戳不能确立真实语音结束或生产交付之前的就绪。另一项实现路径比较则并非 token 等价。因此，本文贡献的是一个可检验的状态契约与有界的软件层证据，而非关于生产环境打断延迟或用户体验改善的断言。

## 2 相关工作

### 2.1 播放条件化的转录与历史截断

在交互策略层面，最接近的先例会依据播放进度修订对话状态。OpenAI 在客户端提供的音频边界处移除未播放的音频与转录后缀（OpenAI, n.d.）；Azure 类似地在打断后更新回复与会话上下文（Microsoft, 2026）；LiveKit 则暴露了用于截断被打断语音的框架级语义（LiveKit, n.d.）。这些系统表明，助手消息不必按生成完成与否来完整保留。

它们的公开接口并不能确立其推理内部机制。我们查阅的 OpenAI 与 Azure 文档未披露这些服务是否采用级联架构、助手 token 跨度如何表示，或 KV 状态是否被就地裁剪。LiveKit 暴露了消息与播放行为，但未暴露 transformer K/V 张量、掩码、token 台账、位置与角色/EOT 状态的联合恢复。因此，我们的区别在于**可检视的机制与证据**，而非断言这些系统缺乏某种未公开的实现。它们的播放量同样是软件层的数值或估计，而非对设备呈现或声学接收的直接测量。

### 2.2 流式对话、预期性计算与打断控制

预测式 ASR 利用部分识别结果预测最终输入，并预取一条回复；若最终识别证实预测，则可使用该回复（Schwarz et al., 2023）。LTS-VoiceAgent 将语义触发与增量推理结合（Zou et al., 2026）；RelayS2S 使用回复级候选前缀并配合验证与续写（Mai, 2026）。这些研究确立了"先计算、后提交"（compute-before-commit）作为语音交互的一种相关设计模式。我们的支持性候选研究共享该模式，但测量的是同步预言机接受之前的生成。其候选选择事件并不等价于生产可用性，因为缓存更新、交付授权、消费方准入、TTS 与音频缓冲都可能发生在其后。

打断控制研究主要决定输出应当在何时停止。FireRedChat 在级联与半级联配置中，将流式或个性化语音活动检测与打断控制结合（Chen et al., 2025）。与之不同，联合前缀状态修复始于打断决策**之后**，决定助手轮次的哪一部分保持提交。检测与修复互补，但成功的检测并不意味着下一轮的缓存与对话历史有效。

全双工语音模型提供了另一参照。Moshi 对并发的语音与文本流建模，以支持重叠交互（Défossez et al., 2024）。更紧密的流协调可以避免由独立部署的 ASR、LLM 与 TTS 组件引入的某些边界，但在存在队列与缓冲的情况下，模型流位置、设备呈现与声学接收仍然彼此不同。因此，比较时必须指明所观测的边界，而不能从架构标签推断交付。

《Speech Communication》发表过低延迟、流式与会话研究，构成本文的期刊层面背景。Morrone 等人集成语音分离与语音活动检测，实现电话对话的低延迟说话人分离（Morrone et al., 2024）；Edwards 测量了电信时延如何改变说话人切换时机（Edwards, 2025）；Zheng 等人结合对话历史与热词，为会话 ASR 提供上下文提示（Zheng et al., 2026）。这些工作分别涉及语音处理、时延与会话上下文，均未涉及播放条件化的 transformer 状态回滚。

### 2.3 KV 缓存管理与跨轮状态

自回归 transformer 保留先前 token 的键/值张量，以避免重复计算完整前缀。Transformers 通过缓存抽象暴露该状态，包括 `DynamicCache.crop`（Hugging Face, 2025a,b）。该原语使就地截断成为可能，但既不选择对话边界，也不修复非缓存状态。

服务系统（serving）研究涉及相邻目标。PagedAttention 将 KV 内存组织为非连续块，采用按需分配与写时复制（Kwon et al., 2023）；SGLang 的 RadixAttention 在基数树中管理可复用的 token 前缀（Zheng et al., 2024）。这些方法改进的是内存使用、吞吐量或共享前缀复用，而不是依据软件播放进度选择被打断的助手前缀。IntentKV 依据文本代理的意图剪枝跨轮状态（Li et al., 2026）；Speculative Interaction Agents 围绕异步工具调用协调临时结果（Hooper et al., 2026）。它们的控制信号是文本意图或工具状态，而非 TTS 片段归属与软件已消费采样点。

因此，本工作的技术区别不在于新的缓存表示或裁剪算子，而在于：它将外部软件进度信号耦合到一个合法的对话前缀上，然后在该前缀的所有表示上进行一次性的联合修复转换。其验证同样具体：对同一裁剪前快照的直接切片，检验所请求的 K/V 前缀是否被保留；错误长度对照，检验该关卡能否拒绝边界错误；匹配恢复，检验相等的保留状态在相同的后续 token 块与操作下是否保持相等。这些关卡不确立与独立重算前缀的等价性、后续回复的语义正确性，或跨推理引擎的可移植性。

我们于 2026 年 9 月 3 日冻结了一次有针对性的公开来源检索，覆盖跨出版商索引、arXiv、ACL Anthology、ISCA Archive、ACM Digital Library、IEEE Xplore、NeurIPS 论文集、DOI/Crossref 元数据，以及第一方产品与代码仓库来源；检索词组合了级联语音对话、打断、预期性回复生成、缓存回滚与播放感知历史。在已报告且可访问的来源中，未发现任何可公开检视的级联实现同时披露完整的"游标—片段—token—缓存—角色"路径以及可复现的直接完整性与恢复证据。部分来源因自动化访问限制而无法访问；该检索既非系统性综述，也非专利检索。这是一个**有界的"未识别到"结果**，而非"全球首创"式断言。

## 3 系统模型与问题形式化

### 3.1 级联流式系统

考虑级联式语音对话系统

$$
\mathcal{S}=\langle\mathrm{ASR},\mathrm{LLM},\mathrm{CHK},\mathrm{TTS},\mathrm{PLY}\rangle,
\tag{2}
$$

其组件以增量方式通信。流式 ASR 将一段话语转换为稳定的文本段 $U=\langle u_1,u_2,\ldots\rangle$；下游处理只消费最终（final）片段，而非可变的局部假设。LLM 对这些片段增量预填充，并生成助手内容 $Y=\langle y_0,\ldots,y_{G-1}\rangle$，其中 $G$ 为当前内容端点。

切分器（chunker）将解码后的助手输出切分为完整的文本片段 $F=\langle f_1,\ldots,f_m\rangle$ 供 TTS 使用。每个片段在助手内容 token 轴上拥有一个连续的半开区间：

$$
f_j\mapsto[\operatorname{ts}(f_j),\operatorname{te}(f_j)),\qquad
\operatorname{ts}(f_1)=0,\qquad
\operatorname{ts}(f_{j+1})=\operatorname{te}(f_j).
\tag{3}
$$

片段是**保留的原子单元**，因为系统在合成音频与文本之间没有词级、音素级或 token 级的对齐。流式 TTS 将每个片段变换为一个或多个音频块（chunk）。一旦注册，片段 $f_j$ 便在采样率 $r$ 下占据累积采样区间 $[\operatorname{ss}(f_j),\operatorname{se}(f_j))$。播放器上报具有计数语义的游标 $p\in\mathbb{N}$：$[0,p)$ 已在软件中被消费。

### 3.2 软件保留边界

在时刻 $t$，令 $G(t)$ 表示已生成内容端点，$S(t)$ 表示在 TTS/软件时间线上注册的最大 token 端点。由于 $p(t)$ 位于采样轴上，无法与 $G(t)$ 或 $S(t)$ 直接比较。若在计数约定

$$
\operatorname{ss}(f_k)<p\leq\operatorname{se}(f_k)
\tag{4}
$$

下，游标 $p$ 落在片段 $f_k$ 内，则片段级保留边界为

$$
\widehat H(p)=\operatorname{te}(f_k).
\tag{5}
$$

当游标落在 $f_k$ 内部时，边界被**有意向上取整**到完整片段端点；另设一个单独的"部分"（partial）标志记录片段内的命中。当 $p=0$ 时，$\widehat H(0)=0$；超出已注册音频的游标被钳制到最后一个具有音频记录的片段。

在"播放只消费已注册片段、片段按生成顺序进入时间线"的生产者顺序假设下，

$$
\widehat H(p(t))\leq S(t)\leq G(t).
\tag{6}
$$

这是应用时间线上的不变量，而非声学传播模型。反向查询为

$$
\Phi:p\mapsto f_k\mapsto
[\operatorname{ts}(f_k),\operatorname{te}(f_k))\mapsto\widehat H(p).
\tag{7}
$$

它是跨采样点、音频块、片段与 token 跨度的**关联**，而非可逆对齐。图 2 展示了三个进度量被映射到同一 token 域之后的情形。

> **图 2**　转换到 token 域之后的已生成进度、已注册进度与软件已消费进度。位于 $f_3$ 内部的游标选择其所在片段的完整端点。
>
> ```text
>  0         f₁         f₂         f₃         S(t)
>  ├──────────┼──────────┼──────────┼──────────┤ ⋯⋯ G(t)
>                        ▲   p
>              （游标 p 落在 f₃ 内部）
>                                  ▲
>                   保留片段边界：Ĥ(p) = te(f₃)
> ```

仅为下游分析之便，用字符比例

$$
\alpha(p)=\frac{p-\operatorname{ss}(f_k)}{\operatorname{se}(f_k)-\operatorname{ss}(f_k)}
\tag{8}
$$

近似部分消费的片段尾部。对片段长度 $L_k$，原始切分位置 $\operatorname{round}(\alpha(p)L_k)$ 会被回退到最近的空白字符边界。该代理量**不用作裁剪点**，且既非 token 线性，也非声学对齐。

### 3.3 持久联合前缀状态

打断修复不是仅针对 KV 对象的操作。我们将持久状态定义为

$$
\mathcal{Z}=\langle\mathcal{K},M,I,A,\varphi,e,a_0,a_1\rangle,
\tag{9}
$$

其中 $\mathcal{K}$ 为动态 KV 缓存，$M$ 为注意力掩码，$I$ 为完整 token-ID 台账，$A$ 为当前助手内容台账，$\varphi$ 为角色阶段，$e$ 为生成结束原因，$[a_0,a_1)$ 为绝对助手内容跨度。每个稳定状态都满足

$$
|I|=|M|=\operatorname{seq}(\mathcal{K}),\qquad A=I[a_0:a_1].
\tag{10}
$$

后续预填充的位置由每次操作之后的实际缓存长度推导。

角色阶段取三种状态：`USER_OPEN`、`ASSISTANT_OPEN` 与 `ASSISTANT_EOT_PENDING`。结束原因显式区分：无、模型选择的 EOT、达到最大 token 终止、消费方停止与裁剪。被选中的结构性 EOT 会将角色推进到 `ASSISTANT_EOT_PENDING` 并记录 EOS，但**不**进入 $\mathcal{K}$、**不**追加到 $A$、也**不**准入 TTS。其后的角色重开操作是唯一的关闭提交，恰好追加一个由模板派生的 assistant 关闭序列，随后是 user 开启 token。

对于播放打断，相对边界被转换为绝对端点

$$
N=a_0+\widehat H(p).
\tag{11}
$$

修复后的状态必须：将 K/V、掩码、全局台账、助手台账与内容跨度缩短到同一语义边界；移除对被丢弃内容的所有访问；从保留前缀继续位置编码；并赋予与保留 token 序列一致的角色/结束状态。

两个零内容情形彼此不同。$\widehat H(p)=0$ 的播放打断会裁剪到 $a_0$，保留 assistant 头部并保持 assistant 角色开启，之后再正常关闭；而对未被接受候选的完全作废，则回到推测前的 `USER_OPEN` 端点，同时移除 assistant 头部与候选内容。混淆这两种情形，要么会凭空制造一个空的助手轮次，要么会抹掉一个已进入输出路径的轮次。

## 4 播放条件化的联合前缀状态修复

### 4.1 片段关联与生产者契约

每条时间线记录包含

$$
\langle f_j,\,[\operatorname{ts},\operatorname{te}),\,C_j,\,
[\operatorname{ss},\operatorname{se}),\,s_j\rangle,
\tag{12}
$$

其中 $C_j$ 是有序音频块列表，$s_j$ 是片段生命周期状态。生成侧注册冻结的 token 跨度；TTS 挂接音频块并推进累积采样轴；播放器推进 $p$。打断发生时，$\Phi$ 定位命中片段并返回其 token 端点（图 3）。

> **图 3**　片段关联记录。TTS 片段将一个助手 token 跨度与其有序音频块及累积软件采样区间链接起来。
>
> ```mermaid
> graph LR
>   T["助手 token 跨度 [ts, te)"] --> F["TTS 文本片段 f_j"]
>   F --> A["所属音频块 C_j"]
>   A --> S["软件采样点 [ss, se)"]
>   S -. 游标查询 Φ .-> T
> ```

只有写侧约束成立时，反向查询才有效：片段跨度必须非空、单调且连续；片段只有在其跨度冻结后才接受音频，终结片段不再接受新的音频块；每个音频块标识符全局唯一；采样区间必须非空、有序且连续；软件游标单调，且不能推进到已注册采样点之外。乱序片段、重复或错配的音频块、空隙、重叠、关闭后追加以及游标回退都会被**拒绝**，而不是被静默重排。

切分器看到的是解码文本而非 token 标识符。为将片段关联到 token 端点，该方法累计每个解码 token 贡献的非空白字符，并在该累积序列中定位片段的非空白长度。纯空白片段被跳过；端点被钳制到观测内容长度；各片段非空白序列的拼接必须与原始解码序列相等。该过程确立了确定性的软件边界，而不主张声学对齐。

### 4.2 可作废的候选生成

设轮次完成度模型为累积的稳定转录赋予置信度

$$
c_i=\operatorname{conf}(u_1\cdots u_i)\in[0,1].
\tag{13}
$$

当 $c_i\geq\theta$ 时，系统把当前 `USER_OPEN` 状态存为**推测前快照**，开启 assistant 角色，并生成至多 $B$ 个候选内容 token；该预算约束了误触发产生的 token 量。

若另一个稳定 ASR 段到达，则活动候选被完全作废：联合状态回到保存的 user-open 端点（包括移除 assistant 头部），并对被丢弃的候选 token 计数。裁剪之后 `CROPPED` 状态仍可观测；新用户文本成功预填充后，当前结束原因被重置。在最终的终点事件处，存活的候选可以继续，或新开一个 assistant 角色。

首个候选回调发生在 token 选择之后，但先于缓存更新的前向计算与生成器产出。它**仅**表示内部的"选择/计算就绪"，不表示交付授权、TTS 准入、设备呈现或声学输出。本试验台使用候选之后的同步预言机；独立的在线交付门控不在所评估机制范围内。

### 4.3 联合裁剪与角色恢复

给定合法端点 $N$，裁剪将每个 K/V 层沿其序列维度缩短，并将 $M$、$I$、$A$ 与 $[a_0,a_1)$ 截断到同一前缀；赋予与保留结构一致的角色阶段，并把当前结束原因标记为 `CROPPED`。落在结构性角色或 EOT token 内部的端点会被拒绝。

对播放打断，命中片段及其之前的片段保留在 $A$ 中，之后的内容从所有缓存与台账表示中消失。当没有保留任何助手内容时，assistant 头部保留、角色仍处于开启状态。随后，角色重开操作恰好追加一次模板派生的 assistant 关闭与 user 开启序列。若该序列含 $q$ 个 token，则重开后状态满足

$$
|I|=|M|=\operatorname{seq}(\mathcal{K})=N+q,
\qquad |A|=\widehat H(p).
\tag{14}
$$

结构性 token 进入 $\mathcal{K}$、$M$ 与 $I$，但**不**进入 $A$；下一轮用户文本从位置 $N+q$ 开始。

完全候选作废则裁剪回 assistant 头部之前保存的 user-open 端点，且不插入 assistant 关闭序列；`CROPPED` 状态持续到下一个用户段被追加为止。图 4 总结了播放情形与唯一的结构性关闭。

> **图 4**　联合裁剪与角色恢复。唯一的关闭/重开转换提交结构性 EOT，而不在助手内容中重复它。
>
> ```mermaid
> graph LR
>   A["已生成状态：<br/>保留 + 被丢弃内容"] --> B["在 N 处原子裁剪：<br/>KV、掩码与台账"]
>   B --> C["恢复角色阶段<br/>与内容跨度"]
>   C --> D["提交唯一的关闭序列<br/>与下一个 user-open"]
> ```
>
> （图内注：被选中的 EOT 保持为待定的结构状态，不属于助手内容。）

只编辑文本而不移除其 K/V 表示，会使模型仍然以被丢弃内容为条件；只缩短 K/V 而不截断掩码与台账，会使长度与位置失效。联合修复使同一保留前缀在 token 空间与模型状态中**都**可检视。

### 4.4 精确性验证

直接裁剪完整性在每个裁剪事件处比较三种状态：从裁剪前生产状态提取的前缀、一次生产裁剪后的状态，以及从同一裁剪前快照克隆的**切片预言机**（slicing oracle）。该预言机把每个 K/V 张量连同掩码与全局 token 台账直接切片到推导出的长度；它不调用生产裁剪接口。尽管如此，它是**同快照预言机**，而非外部实现或干净重预填充参照。

冻结的网格包含 24 个有序用例，覆盖 512、2048 与 8192 token 上下文；零内容保留；精确边界与片段中部边界；回复尾部移除；待定 EOT；完全作废；后续用户轮次；以及第二次裁剪。这些用例产生 27 次裁剪事件，其中包括三次空操作（no-op）。全部 308 个助手夹具（fixture）token 均通过生产累积路径追加。

对每个事件，目标长度由用例、片段划分以及角色/内容边界**推导**得出，而不是信任记录中的保留值。验证逐层比较 K/V 的形状、dtype、设备、SHA-256 与运行时逐元素相等性，并同时比较掩码、token 台账、序列长度、内容跨度、角色阶段与结束原因。每个事件都必须使一次性的错误长度对照失败（即被检出）。

裁剪后，生产分支与预言机分支在 60 个匹配恢复步中接收完全相同的 token-ID 块与角色/状态操作；每步之后比较 K/V、logits、掩码、台账、保留前缀哈希以及独立推导的角色/结束/内容状态。我们称之为**同次运行内匹配分支恢复精确性**（within-run matched-arm recovery exactness）。它的含义是：两个完全匹配的保留状态，在已获采纳的同一次运行中、在相同操作下保持相等。它不意味着跨进程、跨设备、跨版本、跨精度或跨后端的确定性，也不确立干净重预填充或续写等价性。

### 5.4 下游固定轨迹探针

E3 包含 100 段对话、400 个"对话—注入位置"配对单元、800 条条件记录与 1600 条评判记录。每条助手轨迹只生成一次；软件游标条件与完整生成保留条件共享该轨迹、其片段时间线以及四个注入位置（0.25、0.50、0.75，以及一个片段边界）。片段目标与字符比例代理目标分别在各自目标字符串非空时具备入选资格。

主要估计量（estimand）为：对每个合格的"对话—位置"标签等权重，计算"生成 − 软件游标保留"。置信区间采用 10,000 次按对话簇配对的自助重抽（bootstrap）。对话加权敏感性分析先在对话内取平均。针对目标的精确键去重组合了对话与轨迹标识、两个历史键以及精确目标哈希；片段键还包含保留的 token 端点。它**不是**语义聚类。

词面（lexical）检测器匹配数字、选定的首字母大写词以及非停用词内容词。`specific-reference-v3` Mistral 评判器接收目标与两条以分隔符连接的回复（不告知条件身份），并以贪心方式给出严格的 YES/NO 判定。两种检测器都不是人类参照标准。

### 5.5 候选生成刻画

确证性的 C-E1/C-E2 使用 100 条唯一的留出话语、五个独立初始化的进程会话与十个条件。每个条件包含 500 个"会话—话语"观测，但内容采样单元仍是 100 条话语。正式推断使用 10,000 次交叉/乘积 bootstrap 重复：独立地对会话与话语重采样，并按其笛卡尔积的重数进行评估。

试验台同步交付预先切分好的文本；它不包含真实音频、ASR 墙钟时间、在线轮次检测器计算、TTS、播放与声卡。`first_token_ready` 发生在候选 token 选择之后、缓存更新完成与生成器产出之前，因此被报告为"候选选择/就绪"。`endpoint_accept` 是候选之后的同步预言机，而非自然终点检测器。因此，有效 TTFT（effective-TTFT）量是一个乐观的预言机下界。

C-E2 比较 token 一致的 B@0.92 路径与永不触发（never-trigger）路径。在全部九个 B 路径点上，候选选择/就绪保持在 62.0–62.4 ms。在 B@0.92 下，预言机接受时刻的候选可用率为 67%（335/500），交叉 95% CI 为 [58%, 76%]；合并的丢弃 token 比例为 2.85% [1.12%, 4.73%]。后者是 token 数量之比，而非 FLOPs、GPU 时间、能耗或带宽之比。相对永不触发，就绪差异（永不触发减 B@0.92）为 −0.03 ms [−0.64, 0.61]，而预言机延迟下界差异为 +20.80 ms [17.85, 23.65]。在九个离散点上，阈值越低，候选可用率与合并丢弃 token 比例越高，而"从到达点到候选就绪"的时间保持在 62.0–62.4 ms。这些发现刻画的是同步预言机接受之前的生成；它们并未证明真实语音结束之前的就绪。

C-E1 比较整串分词/整段预填充与分段分词/增量前向。就绪均值分别为 27.70 与 62.38 ms，A 减 B 差异为 −34.69 ms [−35.44, −33.95]；预言机下界均值分别为 27.70 与 10.26 ms，差异为 +17.44 ms [14.41, 20.32]。完整 token 输出仅在 280/500 对中匹配；44/100 条话语在至少一个会话中出现分歧。因此该对比混合了分词、前向拓扑/形状、角色边界、内核与 Python 调度；它无法识别增量预填充效应，而只挑选输出匹配的对将构成基于结果的事后选择（post-treatment selection）。

最后，A2 为每种自然化实现生成 100 条记录。自动连贯性评分均值为：朴素保留 3.76、轻量重写 3.62、打断标记 3.29。重写平均耗时 639 ms（中位数 670 ms；插值 P90 约 935 ms；最大 1165 ms）。由于各条件重新生成了初始回复与后续回复、且仅在 33/100 段对话中共享兼容的保留文本，这些数值不能估计策略效应。它们是探索性描述，而非负面或零结果。

## 6 讨论

### 6.1 联合状态契约，而非新的裁剪原语

本文贡献既不是作为一般原则的播放条件化历史截断，也不是作为孤立操作的 KV 裁剪——二者均有先例。本文贡献的是一份**外部进度条件化的联合前缀状态契约**：它规定了观测到的软件播放位置如何成为合法的语言模型提交边界，以及在该边界处每一个依赖前缀的表示如何被修复。

C2 为该契约提供了直接证据。在冻结配置下，每次生产裁剪都保留了与其自身裁剪前快照的直接切片完全相同的 28 层 K/V 前缀；所有已知错误长度扰动均被检出；匹配的后续操作在已采纳运行内保持完全一致。该证据超越了缓存长度检查，因为它涵盖掩码、token 台账、助手内容跨度、角色阶段、结束原因、位置以及裁剪后的 logits。它仍比"干净重建"测试更窄。v1/v2 协议在失败后未被重新解读；其前向拓扑失配使其数值差异无法归因于裁剪。C2 v3 转而回答一个可识别的同快照完整性问题。

最重要的推论是：**转录校正与缓存校正不可分离**。仅截断文本，会让被丢弃内容仍可通过 K/V 状态访问；仅裁剪张量，则会让掩码、位置、角色结构或审计台账停留在不相容的端点。结构性 EOT 需要特别注意：把预测出的 EOT 当作助手内容、之后又追加另一个关闭标记，会悄然改变序列化后的对话。待定的结构状态与唯一的关闭提交防止了这种重复。

### 6.2 支持性结果及其局限

A1 显示了在其固定协议下，保留已验证前缀为何可能有用。随上下文增长，联合裁剪与角色修复保持在相对窄的时间范围内，而重预填充的增长足以使中位比值在 8192 token 处达到 40.620×。该结果不是等价性证明，且操作顺序与后缀长度均为固定。P1 同样描述的是就绪状态下的无头路径；其软件确认与裁剪端点不包含 TTS 取消、声卡缓冲或声学停止。两个实验系列均不支持生产环境端到端延迟的断言。

E3 检验在固定的自动化测量下，所选边界之后是否存在可检出的信息复现差异。四个"生成 − 软件游标"点估计均为负，但其置信区间跨零，且未预先设定实质性边际。该结果既不支持益处也不支持危害，且无法确立等价性或非劣效性。片段目标依赖 TTS 切分；代理目标引入字符比例近似；词面规则与单模型评判器操作化了不同的构念。精确键去重移除的是重复的键权重，而非识别语义重复。因此，E3 是一个有界的下游诊断，而非关于可感知连贯性、信任或对话质量的证据。

C-E2 把候选计算与接受分离开来。其就绪对比接近于零，而其同步预言机下界对比为正，原因在于已经存在的候选不计入接受后的等待。335/500 的候选可用率以全部条件记录为分母，而不仅是已启动的候选。丢弃 token 比例度量的是 token 数量，而非计算量、能耗或内存流量。C-E1 的隔离性更弱，因为其路径并非 token 等价；其时序对比不能归因于增量预填充。

探索性的 A2 分数混合了不同的首轮回复、切分边界与后续生成；它们不能估计朴素保留、标记或重写的效应。重写与用户语音的潜在重叠也仍是一种架构上的可能性，而非实测的延迟降低。

### 6.3 效度威胁

#### 6.3.1 构念效度

软件游标不是设备采样时钟，也不是对声学接收的测量。应用队列、音频 API、操作系统调度、驱动、设备缓冲与传播可能使三个边界彼此分离。因此，P1 的零软件泄漏采样点不能被解读为设备级或声学零泄漏。

E3 的目标与检测器都是代理。在没有盲评人类标注或用户研究的情况下，它们无法测量可感知的语义保真度、自然度、对话成功度或信任。同步候选试验台度量的同样是程序事件，而非自然的语音结束。

#### 6.3.2 内部效度与结论效度

C2 的精确关卡覆盖有限且确定性的网格，并非运行错误率的估计。A1 固定了操作顺序与裁剪长度。P1 每格 20 个观测，经验 P95 依赖一两个上尾值。E1/E2 在五个进程会话中复用 100 条话语；交叉重采样反映两个被观测维度，但不反映日间、负载或部署变异性。C-E1 缺乏 token 等价性。E3 在部分目标上包含重复的精确键；其区间也未纳入检测器、提示、模型或人类评判的不确定性。

#### 6.3.3 外部效度

证据集中于英文任务型 MultiWOZ 对话、Qwen2-7B-Instruct、类 ChatML 角色结构、Transformers `DynamicCache`、BF16/SDPA 与 RTX 3090 GPU。其他语言、分词器、TTS 切分、对话模板、精度、注意力后端与推理引擎可能定义不同的合法边界与状态转换。没有任何实验包含真实的"流式 ASR—异步 TTS—音频设备"环路、环回波形、网络拥塞或生产并发。因此，结果只适用于被测软件运行时与协议，而不适用于声学停止、从嘴到耳的延迟、生产交付或用户体验。

### 6.4 迁移条件

迁移所需不止一个缓存裁剪原语：TTS 必须暴露文本片段与音频块之间的归属关系；播放必须上报可解释的进度位置；推理后端必须在联合更新掩码、位置、token 台账、内容跨度、角色阶段与结构性 EOT 的同时，保留或重建合法前缀。每种对话模板都需要自己的序列化与关闭/重开规则；每个后端都需要对合法裁剪点与恢复重新测试。

不透明的音频流需要额外的对齐与缓冲插桩。词级时长、设备时钟或环回波形可以把观测边界移近设备呈现或声学接收，但每一步都会改变所测构念。更广的断言还需要异步终点门控、TTS 准入与取消、共享时钟事件轨迹、真实缓冲与并发、人类标注，以及跨语言或跨后端复现。

## 7 结论

本研究将级联式语音对话系统中的打断上下文校正形式化为**外部进度条件化的联合前缀状态修复**。软件已消费采样点游标经由 TTS 片段被解析为合法的助手 token 提交边界；此后，KV 缓存、注意力掩码、token 台账、位置、内容跨度、角色阶段与 EOT 状态被联合变换。

在冻结的仅精确性评估下，生产裁剪相对同一裁剪前快照的逐层切片逐位精确；匹配恢复分支在接收相同 token 块与操作后保持逐步精确。这些发现**仅**支持直接裁剪完整性与同次运行内匹配分支恢复精确性；它们不推翻被拒绝的干净重预填充协议，也不确立跨环境、声学或生产等价性。

其余实验系列是为该结论划定边界，而非扩展它。固定协议测量显示，保留前缀相对重预填充长上下文具有开销优势；而 E3 未能在各种自动化操作化下确定稳定的下游方向。候选研究刻画的是同步预言机与非等价实现路径，而非真实语音结束之前的收益。因此，证据表明：外部软件进度可以被转换为一个可检验、内部一致的前缀状态转换。把该结果扩展到设备呈现、声学接收、其他模型栈、生产延迟或人类交互，需要在每个相应边界处的直接证据。
