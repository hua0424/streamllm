# 第一章 绪论

> 初稿（2026-07-17）。贡献表述遵守 D-006 prior-art 护栏；实验结论引用第六章正式数值。

## 1.1 研究背景与动机

随着大语言模型（Large Language Models, LLMs）的快速演进，智能语音交互正从传统的“指令-响应”模式向自然的“全双工对话”模式转变。在当前的工程实践中，级联式架构（即流式语音识别 $\rightarrow$ 大语言模型 $\rightarrow$ 流式语音合成）凭借其各模块的可控性与强大的复杂推理能力，依然是主流的系统解决方案。

前期研究已针对级联架构的首字延迟（Time to First Token, TTFT）问题，提出流式 ASR 与 LLM KV 缓存增量预填充的联合优化，使 TTFT 摆脱了随语音长度线性增长的约束。然而，低生成响应延迟仅构成了自然对话体验的基础，另一关键要素是系统对用户打断（Barge-in）的处理能力。人类对话中插话现象频繁，系统在被打断后能否保持对话逻辑的连贯性，取决于一个更隐蔽的系统级状态一致性问题：系统内部记录的已生成文本，与用户实际听到的合成音频，是否存在信息错位。

在级联架构中这种信息错位是结构性的：LLM 的流式计算与 Token 生成进度通常快于 TTS 模型的音频合成进度，而合成进度又超前于受实时率（Real-Time Factor）约束的实际物理播放进度。若用户在音频播放中途触发打断，且系统采用朴素策略将“已生成的全部内容”直接写入上下文历史，LLM 将在后续轮次中不可避免地引用用户从未听到的信息（例如生成“正如我刚才提到的……”），从用户角度来看，对话会出现莫名其妙的逻辑断层。实证数据表明，在朴素的生成位置截断策略下，此类“未听内容引用”事件在被打断轮次中的发生率高达 51%。

“对话历史应对齐用户实际听到的内容”这一系统设计原则，已在部分闭源商用系统（如 OpenAI Realtime API[1]、Azure Voice Live[2]、 LiveKit Agents[3]等）中得到初步的工程应用。然而，上述系统大多在受控的转写文本层面进行粗粒度的截断，或强依赖于客户端的播放进度估算。在学术界与开源社区中，目前仍缺乏从 LLM 推理引擎底层出发，通过显式的 KV 缓存实时操作来实现“播放感知（Playback-Aware）”上下文管理的开源实现与系统性研究。本文旨在填补这一工程与学术空白。

## 1.2 问题与挑战

实现严格播放感知的上下文一致性，需要在复杂的级联流水线内部解决四个相互耦合的问题：
1. 跨模块反向精确映射：打断事件发生时，系统通常仅能获取基于时间戳的音频播放进度（毫秒级），而LLM的 KV 缓存截断需要精确的 Token 级位置参数。这要求系统构建“播放采样 $\leftrightarrow$ 音频块 $\leftrightarrow$ 文本片段 $\leftrightarrow$ Token 区间”的四向映射，并支持快速反查。  
2. 底层 KV 缓存截断的合法性保障：在对 LLM 的上下文进行截断时，必须确保KV 缓存长度,注意力掩码（Attention Mask）与位置编码（Position IDs）的三者同步。此外，还需动态重建对话模板的角色边界，以保证后续多轮对话结构的合法性。  
3. 响应时机判定与推测生成的平衡：传统的硬性端点检测常与流式系统的“提前生成”机制相冲突。本文以连续置信度的软触发（Soft Trigger）驱动可作废的推测生成（Speculative Generation）——以一定的冗余计算（作废的 token）换取响应速度（有效 TTFT）；用户继续说话导致推测作废时，需将 KV 缓存回滚到推测起点。  
4. 被截断历史的语义完整性修复：当截断位置落在句中时，碎片化的历史片段可能干扰 LLM 对当前语境的理解，影响后续生成的语义连贯性；需通过打断标记或轻量重写等策略修复。


## 1.3 本文贡献

- **C1（辅助）推测生成调度机制**：以现成 turn-detection 模型输出的连续置信度配推测阈值，驱动可作废、可回滚的推测过程；在本工作的确定性模拟评测中，推测的提交（采用）由用户说完的真值端点触发，真实部署中可增设更高的提交阈值以门控 TTS 播放。在真实数据上给出推测浪费率与有效 TTFT 的九点权衡前沿，拐点处以约 4.5% 的 token 浪费将说完后延迟从 48.5 ms 压至 12.1 ms（第四章 §4.1，第六章 E2/A3）。
- **C2（核心）播放感知的 KV 缓存管理**：反向映射时间轴 + 基于 `DynamicCache.crop` 的显式截断（掩码/位置编码同步）+ ChatML 角色边界重建 + 推测作废回滚的完整机制。打断响应关键路径（反查+截断）实测恒为亚毫秒级且与上下文长度无关；相对重新预填充，KV 复用在 8k 上下文处加速 39.7 倍（第四章 §4.2，第六章 E3/A1）。
- **C3（扩展）被打断历史的处理策略**：朴素截断/打断标记/轻量模型重写三种策略的实现与消融（第四章 §4.3，第六章 A2）。
- **贯穿性贡献**：上述机制的**首个开源、可复现的级联式参考实现**，以及一套含双口径一致性判定与人工仲裁协议的系统评测。

需要明确的边界：贡献 2 的高层理念（历史=听到内容）为商用系统先行实践，本文的创新在于开源可复现的机制级实现与可量化对比；软触发与重写模块均使用现成模型，不构成模型层贡献。
